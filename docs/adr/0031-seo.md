## Context

**M8-4's criteria:**
- `resolveSeo()`: a pure function with field-level precedence and safety overrides (coming soon, preview, non-production, discourage indexing).
- The editor's SEO tab: title, description, canonical (absolute https), OG image, noindex/nofollow, with "inherited from…" hints and length counters.
- `/…/seo`: title template, default description, default OG image, discourage indexing, Search Console token.
- Output: meta, canonical, OG/Twitter, JSON-LD (`WebSite`, `Organization`, `WebPage`/`BlogPosting`, `BreadcrumbList`) with `<` escaped.
- A sitemap per site (V1: `/s/{address}/sitemap.xml`: published, indexable, non-empty archives). In path mode the host's `/robots.txt` allows `/s/`, lists live sites' sitemaps and disallows `/api/`. A site that discourages indexing gets `noindex` and is left out. Canonical and OG addresses are built from the site's base.
- **Testing:** resolver table tests; the sitemap excludes drafts and noindex; JSON-LD escaping.

**What already existed:**
- **The columns** (M1-1): `entry_drafts.seo`, `entry_revisions.seo` and `site_settings.seo`, JSONB, empty. Revisions already copied the draft's `seo` (M5-3, M7-3).
- **The permission:** `site.seo.manage` (Owner, Admin, Editor).
- **The public pages' head** (M5-6): a title (`{title} · {site}`; the site's name for its home; `· Page n`), robots by status, and the favicon links (M6-4).
- **The image checks** (M6-4): `usableImageIds` on save, `publicImages` on render, `MediaPicker`.
- **The overview's checklist:** "Set up search engine details", with nothing to link to.

## Decision

### 1. The data (`seo/settings.ts`, client-safe)

| | Stored in | Fields |
|---|---|---|
| An entry's | `entry_drafts.seo`, published with the revision | `title`, `description`, `canonical`, `ogImageId`, `noindex`, `nofollow` |
| A site's | `site_settings.seo` | `titleTemplate`, `defaultDescription`, `defaultOgImageId`, `discourageIndexing`, `searchConsoleToken` |

**Empty text, false and null mean "inherit".**

**Two readers of the same data:**
- **Strict schemas when saving** (`entrySeoSchema`, `siteSeoSchema`; unknown keys are refused):
  - plain text: no control characters; a title up to 120 characters and a description up to 320 (the counters advise 60 and 160);
  - **a canonical** is empty or an absolute `https` address with a host, no credentials, and none of `\s < > "`;
  - **an image** is a UUID; whether it is usable is the services' check (§4, §5);
  - **a title template** must hold `%title%`, and only `%title%`, `%site%` and `%sep%` (`·`);
  - **a Search Console token** is letters, digits, `-` and `_` only. A pasted `<meta name="google-site-verification" content="…">` has its token taken out of it.
- **Lenient readers when drawing** (`readEntrySeo`, `readSiteSeo`): value by value, defaults for the rest. An older or damaged value never breaks a page, and an unsafe one (a `javascript:` canonical, say) is dropped.

### 2. The resolver (`seo/resolve.ts`, pure)

`resolveSeo({ site, page, flags })` returns each field with its value and **where it came from** (`entry`, `derived`, `type`, `site`, `platform`). The editor's hints come from the same sources.

| Field | In this order |
|---|---|
| **Title** | the entry's own, as typed → the site's name, for its home → the content type's template (none in V1) → the site's template (when not the default) → `%title% · %site%`. Later list pages read "Blog · Page 2". |
| **Description** | the entry's own → derived: a post's excerpt, the first words of the text (≤ 160, cut at a word), a term's description → the site's default → for the home only, the tagline → none |
| **Canonical** | the entry's own → the page's own address under the site's base |
| **Social image** | the entry's own → a post's featured image → the site's default → none |
| **Robots** | the entry's noindex/nofollow, then the safety overrides below |

**Safety overrides, applied last:**
- **The site discourages indexing:** `noindex`.
- **Not live** (coming soon): `noindex, nofollow`.
- **A preview:** `noindex, nofollow`.
- **Not production:** `noindex`.

**"Production"** is the deployment's own setting, `SEARCH_INDEXING` (`allowed` or `blocked`). Unset, only `VERCEL_ENV=production` allows indexing: local, dev servers and Vercel previews never ask to be indexed. E2E sets `allowed`, to test what production serves.

**Open Graph** is `article` for a post and `website` otherwise. **Twitter** uses `summary_large_image` when there is an image, `summary` when not. **Verification** is the site's Google token.

### 3. What a public page says (`rendering/seo.ts`, the site page's `generateMetadata`)

**Only a live page is resolved.** Coming soon, unavailable and not-found pages keep M5-6's head: a title, robots by status and the favicon links. They carry no canonical, no Open Graph and no JSON-LD, so nothing of the site's content shows before it is public.

**What the resolver is given** is what the renderer has already read and checked:
- the published revision: its title, excerpt, SEO, text and featured image;
- the site's settings and default image.

**Addresses:**
- built from the deployment's `APP_ORIGIN` and the site's base (`/s/{address}` in V1, `siteBasePath`);
- never from a request's `Host` or forwarded headers: the page reads no headers at all.

**Images:**
- an image is the widest of its stored `w{n}` variants, never the original, with its alt text and its real size;
- an id that is not a usable image of this site (another site's, a PDF, in the trash, missing) gives no image, and the next one in the order is used;
- every image a page names is tagged `media:{id}` in the page's read (`loadEntry`; the site's read for the default image), so trashing it changes the page at once.

**Merged into Next's `Metadata`** (`seoMetadata`): an absolute title, the description, `alternates.canonical`, robots, `openGraph` (with `og:locale` from the site's language) and `twitter`. The favicon links are kept.

**Structured data** (`seo/output.ts`, `structuredData`) is one `@graph`:
- **`WebSite`**: name, address, language, publisher.
- **`Organization`**: the site's name and address, and its logo (the `logo` variant) when it has one.
- **`BlogPosting`** for a post:
  - its headline is the published title (cut at 110 characters);
  - also its address, description, image and dates (`datePublished`; `dateModified` is when the published revision was made).
- **`WebPage`** otherwise.
- **`BreadcrumbList`**, when there is more than the home:
  - **a page:** its live ancestors by path, with their published titles (`liveTitlesAt`, cached under `site` and `routes`);
  - **a post or an archive:** through "Blog".

  Nothing is invented: no author, rating or price.

**One block per page** (`JsonLd`): `<script type="application/ld+json">{serializeJsonLd(data)}</script>`.
- **The escaping:** `serializeJsonLd` writes `<`, `>` and `&` as `<`, `>` and `&`, and escapes U+2028 and U+2029. No value, however it was typed, can close the script or open a tag.
- **No `dangerouslySetInnerHTML`:** React writes a script's text as it is.
- **No identifiers:** the graph holds no organization, site, entry or term id.
- **No client code:** it is data, not code; the site tree still reaches no client component (`public-bundle.test.ts`).

### 4. The site's defaults (`/…/seo`, `sites/seo-settings.service.ts`)

**The page:**
- **Access:** "SEO" in the site's links (after Menus) and on the overview's checklist, for Owners, Admins and Editors (`site.seo.manage`). Others get the no-access notice, and the server refuses them anyway.
- **The fields:** a title template (with "For example: About us · Harbour Bakery" as it is typed), a default description with a counter, a default social image (the media picker), "Ask search engines not to index this site", and the Search Console token.
- **Coming soon:** a notice says no page is indexed until the site is live, whatever these settings say.
- **States:** "Unsaved changes" with Discard; success shown only once the server has answered; errors at their field.

**Saving (`updateSeoSettings`):**
1. **Permission:** `requirePermission(site.seo.manage)`.
2. **Checked:** strictly (`siteSeoSchema`). A default image new to the settings must be a usable image of this site (`usableImageIds`); another site's, a PDF, one in the trash or a missing one is refused at the field.
3. **Unchanged:** the same values change nothing; nothing is written, recorded or flushed.
4. **Versioned:** at the settings version the other groups use, so someone else's save since, of any group, is a Conflict.
5. **Recorded:** `site.settings_changed` with group `seo` and the fields that changed. Never their values.
6. **Flushed:** `site.seoChanged`, which flushes `site:{id}:config` (the site's pages) and `robots` (the host's list, §7) at once.

**The checklist** counts SEO as set up once anything differs from the defaults.

### 5. The editor's SEO tab (`content/editor/seo-panel.tsx`)

**The tabs:** the settings panel has two, "Page" or "Post", and "SEO". Arrow keys move between them; each panel is labelled by its tab.

**What it shows:**
- **A preview:** the address, title and description as a search result might show them. It is worked out by the same `resolveSeo()` the site uses, from the draft as it is now, the site's settings and this deployment's indexing.
- **Each field's hint:** its own value, or where it inherits from: "Inherited from the site's SEO settings", "from the excerpt", "from the first words of the text", "from the featured image", "from Forge's default". The inherited value is the field's placeholder.
- **Counters:** title and description length against what search results show (60 and 160), marked past it.
- **The canonical:** checked as it is typed; "Use a full address starting with https://." is announced at the field.
- **The social image:** the media picker, a thumbnail and Remove. An image no longer usable says so and falls back.
- **Robots:** noindex and nofollow. Notes say when the site, its status or the deployment overrides them.

**Saving:**
- The tab saves with the draft (autosave). `saveDraft` checks `seo` strictly, and a social image new to the draft with `usableImageIds`. Errors are keyed `seo.ogImageId`.
- Publishing carries the draft's `seo` into the revision, as M5-3 already did, and the public page reads the published one. A later draft changes nothing on the site until it is published.
- Restoring a revision brings back its SEO (M7-3). Its image is checked again when the page is drawn.

### 6. The sitemap (`/s/{address}/sitemap.xml`)

**Routing:** the proxy rewrites the address like any page of the site, to `render/[site]/sitemap.xml/route.ts`.

**Only a live site that allows indexing has one.** Otherwise the answer is a plain 404 with `X-Robots-Tag: noindex`:
- a site that is coming soon, suspended, deleted or unknown;
- a site that discourages indexing.

No list of a site's content leaks before it is public.

**What it lists** (`loadSitemapRows`, then `sitemapUrlsOf`):
- **The home:** the Home page, or the site's own home while it has none. Left out if the Home page is noindex or names another canonical.
- **Every other live entry that is indexable and its own canonical:**
  - live means published, not in the trash, and in the site's language (the same `live` rule as every public read);
  - an entry marked noindex is left out;
  - so is one that names another canonical: it says it is a copy.
- **The blog**, when it has posts.
- **Each category and tag with live posts.**

Page 1 of each list only. Up to 45,000 entries; a sitemap index is post-V1.

**The format:**
- XML with every value escaped;
- `<lastmod>` is the date the published revision was made;
- `Content-Type: application/xml; charset=utf-8`, `X-Robots-Tag: noindex` (the file itself is not a search result).

**Caching:**
- **The rows** are one `'use cache'` read tagged `site`, `routes`, `list:post` and `list:page`. Publishing, unpublishing, the trash, a move and a term's change each flush `routes` at once.
- **The site's status and SEO** come from `loadPublicSite` (`config`, `site`).
- **The route itself** answers per request (`connection()`), never as a prerendered response.

### 7. The host's robots.txt (`app/robots.ts`, path mode)

**What it says:**
```
User-Agent: *
Allow: /s/
Allow: /media/
Disallow: /api/
Disallow: /_forge/
Sitemap: https://{APP_ORIGIN}/s/{address}/sitemap.xml   (one per indexable site)
```
- `/_forge/` is where previews live.
- The admin's pages are not listed by path: they sit behind sign-in, and every one says `noindex, nofollow` (its layout's metadata).
- **Not production:** `Disallow: /`, and no sitemaps.

**Which sites are listed** is a cross-tenant question, answered without widening the app's access (migration `0015_indexable_sites_lookup`):
- **The function:** `indexable_site_addresses(limit)` is `SECURITY DEFINER`, owned by `forge_lookup` (NOLOGIN) like the earlier lookups, and only `forge_app` may run it.
- **What it returns:** addresses only, of sites that are live, not deleted, with an active platform address, and not discouraging indexing.
- **What it may read:** `forge_lookup` gets column grants on exactly what the function reads, behind policies: `sites` (id, organization, status, deleted; live and not deleted only), `site_settings` (site, organization, `seo`) and `domains` (site, organization, hostname, kind, status).
- **What `forge_app` sees** of the tables directly is unchanged.

**Caching:**
- **The list** (`indexableSiteAddresses`, at most 5,000) is cached under the tags `robots` and `host:{hostname}`.
- **What flushes it, each at once:**
  - `site.statusChanged` (now `site` and `robots`): going live, or back to coming soon;
  - `domain.changed` (now with `robots`): an address change or a deletion;
  - `site.seoChanged`: discouraging indexing.
- **The file** is answered per request (`connection()`): the build has no database, and is not the deployment it serves (`SEARCH_INDEXING` is read at runtime).

### 8. A social image is a use of the file

The media trash's warning (M7-1, `usageOf`) now counts:
- an entry's social image, published or in a draft, as a page or post that shows the file;
- the site's default social image ("It is the site's default social image: pages shared without an image of their own go without one.").

Trashing such an image still works; the page falls back at once (§3).

## Not in M8-4

- **A 1200 × 630 crop for social images** (plan §10): the widest stored width is used, at its real size; no crop is made and the original is never served. A crop variant could be added to the processing ladder.
- **Host mode** (a site on its own host, post-V1): a `robots.txt` and `sitemap.xml` per host. `robotsRules` and `sitemapUrlsOf` take the base and origin as arguments for that.
- **Redirects:** M8-5. Its `/…/seo/redirects` sits under this page.
- **A sitemap index** past 45,000 entries; image sitemaps; `hreflang`; RSS.
- **SEO scoring or analysis**, Twitter handles, per-type title templates in the admin (the resolver has the slot).
- **Analytics:** GA4 and Plausible stay disabled, pending the consent and privacy decision. Nothing here emits a tracking script.

## Why, and what it costs

| Decision | Reason | Tradeoff | Reconsider when |
|---|---|---|---|
| One pure resolver, with each field's source, used by the site and the editor | The hints can never disagree with the site; table-tested | The editor sends the site's settings to the browser (nothing private: what the site shows) | — |
| Safety overrides last, `SEARCH_INDEXING` off by default outside Vercel production | No preview, dev server or staging copy is ever indexed by mistake | E2E and any production outside Vercel must set it | A second production host |
| Addresses from `APP_ORIGIN` and the site's base only | A forged `Host` or `X-Forwarded-Host` cannot change a canonical | Host mode will need the site's primary host instead | M9 / host mode |
| Only live pages resolved; other states keep M5-6's head | Nothing of a coming-soon site's content reaches a crawler or a share card | Coming-soon pages have no description | — |
| JSON-LD as escaped text in a script, no `dangerouslySetInnerHTML` | No title can close the script; React escapes nothing inside a script, so the serializer must | One serializer to keep right (unit- and E2E-tested) | — |
| The widest stored width as the social image | Never the original (EXIF, size); the variants exist already | Not cropped to 1200 × 630; very tall images show cropped by the platform | Owners ask for a crop |
| Image ids checked on save and again on render | JSON with no foreign key; an image can be trashed after it is chosen | Two checks | — |
| Sitemap rows as their own cached read, tagged like the lists and routes | One query; flushed by everything that changes what is live | Re-read on every publish | Sites grow past tens of thousands of entries |
| A `SECURITY DEFINER` function for robots.txt, addresses only | The one cross-tenant read returns only what `/s/{address}` already shows | One more function to keep in step with the status and SEO rules | Host mode |
| robots.txt and the sitemap answered per request, their data cached | A prerendered file would freeze the build's database and indexing setting | A function call per request (the data is cached) | — |
| SEO defaults at the shared settings version | One version per settings row; a stale tab cannot overwrite another group | A save elsewhere makes this form's save a Conflict | — |
